# Edu Task Topic Classifier

**От условия задачи — к предмету и темам учебной программы.** Классификация русскоязычных задач по математике и физике с частичной иерархической разметкой, проверкой утечек и обучением ruBERT на Apple Silicon.

Проект объединяет подготовку данных, TF-IDF baseline, многозадачный трансформер и анализ результатов. Модель получает **только условие `task`**. Ответы, решения, названия тем, ID и служебные признаки не входят в текст модели. Практический сценарий — предварительная разметка каталога задач для последующей проверки преподавателем.

[Пошаговый исследовательский ноутбук](notebooks/01_project_walkthrough.ipynb) · [Формат данных](data/README.md) · [Результаты ruBERT](reports/bert/validation_metrics.json)

## Постановка задачи

Предмет — single-label классификация: математика либо физика. Темы — multi-label: задача может относиться к нескольким ветвям дерева. Корни предметов исключены из словаря тематической головы. Назначенная промежуточная тема означает неполную разметку: нельзя автоматически считать все её дочерние темы отрицательными.

В актуальном обучении положительны точные `target_topic_ids`. Их неназначенные предки и потомки маскируются как неизвестные; остальные темы считаются отрицательными. Для отдельной иерархической оценки положительные и предсказанные темы замыкаются предками, корни исключаются. Это разные вопросы: попали ли мы в точную тему и насколько правильно определили ветвь.

## Данные и нормализация

Исходная таблица содержит `id`, `task`, `answer`, `topics_id`, `text_of_solution`; справочник — `id`, `name`, `parent`. Скрипт `scripts/normalize_dataset_v2.py` объединяет повторные строки одного ID, сохраняет исходные записи, строит пути тем, отмечает конфликты и выбирает наиболее конкретные назначенные темы. Отдельные ID с одинаковым текстом не удаляются, а группируются для разбиения.

NFC-нормализация и свёртка пробелов применяются к ключу сравнения. Исходный текст условия сохраняется. Группы `semantic_group_id` используют точный текст либо осторожный числовой шаблон: не менее 8 буквенных токенов и 50 букв, 1–12 чисел, без разметки, URL и цифр рядом с буквами. Знаки, единицы и прочие символы сохраняются. Это эвристика, которая не обнаруживает все перефразировки и не доказывает смысловую эквивалентность.

Целые группы распределяются примерно 80/10/10 внутри предметов, seed 42, с балансировкой числа задач. Темы отдельно не стратифицируются. `prepare` сохраняет назначенные split, проверяет отсутствие пересечений ID, групп и точных нормализованных текстов. Вся группа исключается, если хотя бы одна задача попала в очередь ручной проверки. SHA-256 фиксирует входные файлы и подготовленные артефакты.

## Два подхода

**Baseline:** TF-IDF слов (1–2 граммы, до 50 000 признаков) и символов (3–5 граммы, до 100 000). Предмет и темы предсказывают линейные SGD-классификаторы с логистической функцией потерь. Темы обучаются последовательно one-vs-rest только на известных метках. Векторизаторы обучаются на train. Сохранённые исторические baseline-метрики относятся к прежней версии разметки; текущий код использует новую маску.

**ruBERT:** `ai-forever/ruBert-base` с закреплённой revision, общий энкодер и две головы. Потери предмета и masked BCE тем обучают представление совместно. Неактивные темы отключены; при отсутствии тем выше порога допускается пустой ответ. `predict` оставляет наиболее конкретные выбранные темы и выводит предков отдельно. Текущие головы не обеспечивают жёсткую согласованность предмета и тематической ветви — это направление улучшения. `pmc/labels.py` содержит вспомогательную логику прежней версии и не определяет актуальную маску обучения; актуальный источник — `pmc/hierarchy.py`.

## Обучение на Mac MPS

Полный запуск завершил 6 эпох на MPS, FP32. Конфигурация: batch 1, accumulation 16, длина 128 токенов, AdamW с learning rate 2e-5, gradient checkpointing, фиксированный padding, `foreach=false`. Очистка MPS-кэша выполняется каждые 16 микробатчей; лимит аллокатора 0.65 не равен ограничению всей RAM процесса. Сокращение длины снижает память, но обрезает длинные условия.

Лучшая эпоха выбирается по validation loss, patience 2. В этом запуске лучший loss — 0.06414 на шестой эпохе. После загрузки лучших весов общий порог выбирается на validation по masked micro-F1 из сетки 0.05–0.95 с шагом 0.05. Получен порог **0.85**. Test не используется для обучения или настройки порога. Автоматического resume нет: `last.pt` хранит веса без состояния оптимизатора, новый запуск требует новый каталог.

| Baseline, историческая семантика | Test | Subject accuracy | 0.9940 |
| Baseline, историческая семантика | Test | Старый topic micro-F1 | 0.8456 |

**Эта таблица не является рейтингом моделей.** Отличаются split и семантика метрик: исторический baseline учитывал положительное замыкание предков. Его 0.8456 нельзя напрямую сравнивать с 0.6522. Архивный `model.joblib` также не совместим с форматом текущего CLI. Для честного сравнения нужно заново обучить baseline и оценить обе модели по одному заранее зафиксированному протоколу. Опубликованного test-результата ruBERT здесь нет. Validation использована для выбора эпохи и порога и потому не заменяет независимую итоговую оценку.

Редкие темы — основное слабое место. В отчёте ruBERT F1 равен 0 для 72 тем без поддержки и 26 тем с 1–4 примерами train. Для 162 тем с 5–19 примерами micro-F1 составляет 0.1767, для 403 тем с 20+ — 0.6723. Это группы по поддержке, записанной в отчёте запуска; для анализа нового запуска используйте его собственный `train_support.json`. Среднее по темам заметно ниже micro-F1, поэтому высокая точность предмета не означает надёжной детальной разметки.

## Запуск

Python 3.11–3.12 рекомендуется для закреплённых зависимостей. Команды выполняются из папки подпроекта.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[bert,notebook]'
# Для одного baseline достаточно: python -m pip install -e .

python scripts/normalize_dataset_v2.py --tasks data/raw/tasks.csv --topics data/raw/topics.csv --output-dir data/normalized --seed 42
python -m pmc prepare --source data/normalized --output artifacts/data

python -m pmc train --data artifacts/data --config configs/baseline_smoke.json --run runs/baseline_smoke
python -m pmc train --data artifacts/data --config configs/baseline_full.json --run runs/baseline_full
python -m pmc train --data artifacts/data --config configs/bert_mac_m4_48gb.json --run runs/bert_full

python -m pmc evaluate --data artifacts/data --run runs/bert_full --split validation
python -m pmc predict --run runs/bert_full --text 'Найдите силу тока при напряжении 12 В и сопротивлении 4 Ом.'
jupyter lab notebooks/01_project_walkthrough.ipynb
```

Если три нормализованных CSV уже есть, пропустите нормализацию. Подготовка и обучение требуют новых каталогов; не удаляйте результаты ради повторного запуска. Первый запуск ruBERT скачивает энкодер с Hugging Face. MPS-конфигурация требует Apple Silicon и доступный MPS; для другой платформы создайте копию конфига с поддерживаемым `device`. Повторяемость seed и revision не гарантирует побитовое совпадение на другом оборудовании.

Финальную оценку запускают после выбора модели:

```sh
python -m pmc evaluate --data artifacts/data --run runs/bert_full --split test --final-test
```

CLI резервирует test один раз на подготовленный датасет, в том числе при последующей ошибке оценки. Не удаляйте `TEST_CONSUMED.json` для повторного подбора. Текущий интерфейс рассчитан на один финальный выбранный запуск; совместное итоговое сравнение нескольких моделей потребует отдельного заранее определённого протокола. Исторический baseline test уже был просмотрен, что также нужно учитывать при дальнейших исследованиях.

Проверка без полного обучения:

```sh
python -m unittest discover -s tests -v
python -m compileall -q pmc scripts tests
python -m pmc --help
```

## Ограничения и следующие шаги

1. Провести ручную проверку конфликтных групп и расширить разметку редких тем; отличать отсутствие метки от доказанного отрицания.
2. Переобучить baseline с текущими масками и сравнить на одинаковом validation-протоколе, затем зафиксировать финальную оценку.
3. Проверить длины 256/512 и долю обрезанных условий; отдельно исследовать формулы и изображения, которые текстовый энкодер не интерпретирует как полноценную мультимодальную задачу.
4. Измерить согласованность предмета и ветвей, калибровку и качество отказов; добавить направленную предметом фильтрацию только после оценки её эффекта.
5. Проверить перефразировки между split и перенос на задачи другого источника. Групповое разбиение уменьшает известные утечки, но не доказывает независимость всех формулировок.
6. Добавить интервалы неопределённости, анализ ошибок и контролируемый интерфейс ручного подтверждения.

## Итог

Получен полный исследовательский цикл: от структуры исходных данных и проверки разбиения до воспроизводимых команд обучения и анализа частичной разметки. ruBERT уверенно определяет предмет, а разница между точным и иерархическим F1 показывает, что попадание в область программы проще выбора конкретной темы. Результаты пригодны как основа помощника по разметке, но не доказывают готовность автономного классификатора для всех 663 тем.

Главный вывод — качество здесь зависит не только от мощности энкодера. Корректная семантика неизвестных меток, контроль близких задач между выборками и поддержка редких тем определяют достоверность оценки. Следующий значимый шаг — улучшить данные и сопоставимость экспериментов, а затем оценивать новые архитектуры по тому же протоколу.
